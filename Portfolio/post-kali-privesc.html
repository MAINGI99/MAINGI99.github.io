Kali Linux — Privilege Escalation Lab

2025-03-12 · lab · linux · pentest

Overview

A walk-through of a privilege escalation challenge on a Kali target — from initial recon to gaining root via a misconfigured sudo rule. The goal: understand how small misconfigurations lead to full system compromise.

Environment

ItemValue
TargetKali Linux VM (vulnerable config)
AttackerKali Linux (host)
NetworkHost-only, 192.168.56.0/24
Toolsnmap, ssh, sudo, linpeas

Approach

1. Reconnaissance

Scan the target for open ports and services:

nmap -sV -sC -p- 192.168.56.10

Result: SSH (22) and HTTP (80) open. Web app had a login form.

2. Initial Foothold

Discovered default credentials in the web app. SSH'd in as lowuser.

ssh lowuser@192.168.56.10

3. Enumeration

Ran sudo -l — critical find:

User lowuser may run the following commands on kali:
    (ALL) NOPASSWD: /usr/bin/find

4. Privilege Escalation

Abused the find binary to spawn a root shell:

sudo find . -exec /bin/sh \; -quit

Confirmed with whoami → root.

5. Capture the Flag

Read /root/flag.txt and documented the hash.

Key Lessons

  • sudo -l is the first thing to check after gaining a shell — always.
  • Any binary in GTFOBins with sudo rights = instant root.
  • Default credentials remain one of the most common footholds.
  • Document as you go — the writeup is half the value.
